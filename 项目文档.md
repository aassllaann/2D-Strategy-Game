## I. Project Overview

This proposal is an optimized revision of the original "I Ching Grand Strategy: The Executor" concept, adjusting engine selection, interaction methods, and visual implementation. While fully preserving the core strategy game experience, the development difficulty has been reduced from ★★★★☆ to ★★★☆☆, enabling a 2-person team to complete a playable MVP within 4~5 months.

*   **Core Retained:** Player acts as a strategist, intervening in the tactical situation by interpreting hexagrams; a 64-hexagram state machine drives NPC behavior; multi-ending numerical goal system.
*   **Core Modified:** Engine changed from Unity/Unreal to Godot 4; 3D graphics changed to 2D ink-wash pixel art; free-text input changed to structured options + AI narration.

### 1.1 One-Sentence Pitch

*The Executor* is a 2D ink-wash style strategy + visual novel game: acting as a military advisor, players interpret I Ching hexagrams and select strategic directions to guide AI-generated war narratives, ultimately influencing the fate of the nation.

### 1.2 Target Audience

*   Players interested in traditional Chinese culture and historical strategy (ages 18~40).
*   Fans of visual novels and light strategy games with narrative depth.
*   Steam / itch.io independent game audience.

## III. Core Game Systems

### 3.1 Hexagram State Machine

The core logic layer is a JSON-driven hexagram database consisting of 64 records, each containing the following fields:

| Field | Description |
| :--- | :--- |
| **id** | Hexagram number (1~64) |
| **name_zh / name_en** | Hexagram name (e.g., "乾" / "Qian") |
| **symbol** | Hexagram symbol (e.g., ☰) |
| **nature** | Five Elements attributes and Yin-Yang tendency |
| **npc_tendency** | NPC behavior tendency under this hexagram (for Claude's reference) |
| **yao_rules** | Changing lines rules (which line moves → transform to which hexagram) |
| **image_key** | Key for the corresponding pre-made illustration asset |
| **bgm_key** | Key for the corresponding background music |
| **philosophy_hints** | List of philosophical guidance candidates (AI can use or rewrite) |

> **Design Principle:** The hexagram database is a read-only "world rulebook." All AI outputs must be based on the rules within this database rather than being free-form. This ensures game logic remains predictable and testable.

### 3.2 Interaction Layer: Structured Options + AI Narration

This is the most critical point of differentiation. Instead of letting players input free text—which is unstable for LLM semantic mapping—the process is as follows:

1.  Player sees the current hexagram and the situation description for this turn (generated by AI in the previous turn).
2.  Player selects one of four strategic categories: "Attack, Defend, Plot, Peace."
3.  Under the chosen category, 4~5 specific action options are displayed (e.g., "Plot" → Sowing Discord / Surrender Invitation / Spy Infiltration / Alliance Negotiation).
4.  After selection, the game sends a structured request to the Claude API.
5.  Claude returns a JSON result: Narrative text + line change determination + numerical changes.
6.  Godot parses the JSON, updates the hexagram, plays transformation animations, updates HUD values, and displays the narrative.

> **Key to Difficulty Reduction:** Claude is responsible for only two things: ① Writing compelling war narrative paragraphs; ② Judging which line (yao) changes based on option semantics. Game rule arbitration is handled entirely by Godot code, isolating AI instability within the narrative layer.

### 3.3 Numerical System

Simplified into three core values (0~100). The player's goal is to maintain all three above the critical lines within the turn limit:

| Indicator Name | Meaning | Critical Line |
| :--- | :--- | :--- |
| **National Strength** | Comprehensive national power and strategic posture | Below 20 → Fall of Nation ending |
| **Army Morale** | Military combat will and cohesion | Below 15 → Mutiny ending |
| **Treasury Reserves** | Supply of grain and funds | Below 10 → Famine ending |

After each player action, Claude returns the delta (change amount) for these three values in the JSON. Godot executes the addition/subtraction and triggers UI animations. Values are linked: if Morale falls below 30, Treasury consumption doubles; if Treasury falls below 30, National Strength automatically drops by 2 per turn.

### 3.4 Hexagram Transformation System

At the end of each turn, Godot queries the `yao_rules` in the database based on the `yao_changed` (1~6) returned by Claude to calculate the new hexagram. Animation flow:

1.  Each line of the current hexagram symbol highlights sequentially (~0.8s).
2.  The changing line flashes red with a "Line Motion" sound effect.
3.  The new hexagram symbol flips into view from bottom to top (~1.2s).
4.  Background illustration fades into the new hexagram's image (~0.6s).
5.  BGM cross-fades to the new hexagram's track (~2s).

## V. AI Integration Technical Implementation

### 5.1 Claude API Call Architecture

Create a singleton node `AIManager` in Godot to manage all Claude API calls. Flow:

1.  Player completes choice in `HexagramConsult`, triggering `AIManager.consult(payload)`.
2.  `AIManager` builds the request JSON and POSTs it via `HTTPRequest`.
3.  Upon response, `AIManager` parses `content[0].text` to extract the JSON.
4.  Signals are emitted to broadcast results to `HexagramConsult` and `BattleResult`.
5.  Scenes listen for signals to drive text, animations, and value updates.

> **Error Handling:** If the API times out (>8s) or returns invalid format, `AIManager` triggers `fallback_response()`, picking a default narrative for the current hexagram from a local library to ensure the game continues.

### 5.2 System Prompt Design

The core of controlling Claude's output quality, consisting of four parts:

| Part | Content |
| :--- | :--- |
| **Role Setting** | "You are an ancient military strategist proficient in the I Ching, responsible for interpreting changes and providing analysis. Your style: Concise, elegant, philosophically deep, yet accessible." |
| **Task Spec** | "Based on the current hexagram, player action, and situation values, generate a war narrative and determine which line (yao) changes." |
| **Output Format** | "Must strictly return JSON containing: narrative (max 200 chars), yao_changed (1-6, 0 if none), delta_stats (-15 to +15 for each), philosophy (max 30 chars). No other text." |
| **Constraints** | "Narration must align with hexagram attributes. Numerical changes must be logical based on player actions and current state." |

### 5.3 Request & Response Example

**User Message Example:**
```markdown
Current Hexagram: Qian (☰) —— Primordial Power, Heaven's movement is strong; the superior man strengthens himself.
Current Stats: Strength 62 / Morale 55 / Treasury 48
This Turn's Action: Plot · Sowing Discord (Spread rumors to shake enemy general's trust)
Current Situation: Northern invasion, General Han Ling holds 100k troops; we must neutralize the threat in 3 turns.
```

**Claude Return JSON Example:**
```json
{
  "narrative": "Spies infiltrate Han's camp with a forged letter claiming secret ties to the Western tribes. Within three days, rumors reach the capital, and the Emperor recalls Han Ling for questioning. The northern clouds disperse, yet your own troops are unsettled by the deception.",
  "yao_changed": 3,
  "delta_strength": 8,
  "delta_morale": -5,
  "delta_treasury": -3,
  "philosophy": "Nine in the third place: All day long the superior man is creatively active. At nightfall his mind is still beset with cares. Danger. No blame."
}
```

Godot parses this: `yao_changed=3` triggers transformation from Qian to Kuai (☴); deltas apply to HUD; `narrative` and `philosophy` display in UI.

## VI. Game Loop Design

### 6.1 Session Flow

1.  **Opening Narration:** Introduce current national situation, initial cast of hexagram.
2.  **Main Round Loop** (~15-25 turns/game):
    *   Review current hexagram and situation.
    *   Check World Map for faction dynamics.
    *   Select strategy category (Attack/Defend/Plot/Peace).
    *   Choose specific action (1 of 4-5).
    *   Wait for AI result (~2-4s).
    *   Watch animation, read narrative.
    *   Review stat changes, proceed to next turn.
3.  **Endgame Determination:** Stats hit critical line → Specific bad ending; or turn limit reached → Grade based on total score.
4.  **Presentation:** Ink-wash animation + voiceover + historical lore expansion.

### 6.2 Ending Design (MVP)

| Ending Name | Trigger Condition |
| :--- | :--- |
| **Unification** | All stats > 60 at turn 25 → Best ending, world at peace |
| **Southern Peace** | Strength 40-59, others passing → Good ending, regional stability |
| **So Near Yet So Far** | Strength drops sharply in final 5 turns → Regretful ending |
| **Edge of Mutiny** | Morale < 15 → Army mutiny, forced abdication |
| **Scorched Earth** | Treasury < 10 → Widespread famine, loss of support |
| **Fall of Han** | Strength < 20 → Tragic national collapse |

## VII. Modular Development Roadmap (AI-Assisted Reference)

To guide AI in project breakdown and code generation, the chronological plan is converted into "Functional Modules." AI should follow this structure to ensure high cohesion and low coupling.

### Module 1: Core Data & State Machine

*   **1.1 Hexagram Database**
    *   **Task:** Build/Parse `hexagrams.json` containing 64-hexagram IDs, attributes, transformation matrices, and prompt snippets.
    *   **Guidance:** Create a singleton `DatabaseManager` in Godot that loads and caches this JSON upon initialization.
*   **1.2 Rule Engine**
    *   **Task:** Implement the algorithm to derive the "next hexagram" from "current + changing line."
    *   **Guidance:** Provide a pure logic method `get_next_hexagram(current_id, yao_changed_index)` for external use.
*   **1.3 GameState Manager**
    *   **Task:** Maintain Strength, Morale, Treasury values and turn counts securely.
    *   **Guidance:** Use a `GameState` singleton. Values must only be updated via specific APIs (e.g., `apply_delta(dict)`) which broadcast a `stats_changed` signal.

### Module 2: AI Interaction & Backend Integration

*   **2.1 HTTP AI Manager**
    *   **Task:** Encapsulate Godot's `HTTPRequest` to handle the POST lifecycle.
    *   **Guidance:** Use async signals. Implement a timeout mechanism; network failures must trigger a smooth transition to the local `fallback` library.
*   **2.2 Prompt Builder**
    *   **Task:** Assemble the request by merging context, stats, and player actions into the System Prompt structure.
    *   **Guidance:** Do not pass raw UI text to AI. Maintain standard mappings to ensure consistency in Claude's input.
*   **2.3 Response Parser**
    *   **Task:** Clean and extract the JSON body from Claude's response.
    *   **Guidance:** Be prepared for extra markdown markers or text. Use regex to extract the clean JSON string before calling `JSON.parse`.

### Module 3: UI Components & Scene Orchestration

*   **3.1 Interaction Panel (HexagramConsult)**
    *   **Task:** Build the layered UI (hexagram display, illustrations, action buttons, progress bars, narrative panel).
    *   **Guidance:** Buttons should be data-driven. Disable input layer or show the Loading component during API calls.
*   **3.2 Transformation Orchestrator**
    *   **Task:** Implement visual phases: Cast, Line Motion, Transformation, Reveal New Hexagram with particles/sound.
    *   **Guidance:** Use `Tween` sequences and `AnimationPlayer` instead of hardcoded timers to maintain timing chains.
*   **3.3 Dialogue & Narration System**
    *   **Task:** Handle the "typewriter" effect for narrative text.
    *   **Guidance:** Support `RichTextLabel` with automatic formatting for philosophical guidance.

### Module 4: Game Loop & Lifecycle Manager

*   **4.1 Turn Logic Controller**
    *   **Task:** Govern the sequence: Status Report -> Action Selection -> API Callback -> Settlement -> Update Indicators.
    *   **Guidance:** Trigger strict state locks at each phase and emit signals for phase transitions.
*   **4.2 Ending Router**
    *   **Task:** Review core values at turn end for critical thresholds or turn limit arrival.
    *   **Guidance:** Route the game flow to the ending cinematic/summary module once a condition is met, clearing session memory.
